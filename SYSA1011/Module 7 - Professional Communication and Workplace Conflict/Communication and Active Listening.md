# Communication and Active Listening
Back to [[SYSA1011]] · Prev: [[Organizational IT Resources and Acceptable Use]] · Next: [[Workplace Scenario Practice]]

* Flow: **Listen → Clarify → Communicate**

## Communication changes the outcome
* A good decision delivered poorly can confuse, delay action, sound dismissive, damage trust, miss details, escalate tension
* > **The right answer, delivered wrong, still fails.**
* Professional communication isn't just politeness - it helps people understand **the situation, the impact and the next step**

## Active listening in IT support
* Understand the situation **before jumping to a fix**
* Notice **urgency** · identify what the user is **actually worried about** · ask **clarifying questions** · **confirm the issue back** · separate **symptoms from assumptions**
* Jordan says "the laptop isn't ready" - surface ask: fix the laptop; real worry: **tomorrow's presentation**

## Clarify before responding
1. What does the user need **right now**?
2. What **details are missing**?
3. What's the **business/classroom/operational impact**?
4. What must IT **confirm before promising** anything?
5. **Who else** needs to know?

## Audience
| Audience | Needs |
| --- | --- |
| End user | Reassurance + next steps |
| IT technician | Technical detail + actions |
| Supervisor | Impact, urgency, status |
| Deployment team | Process gap + resolution |

| User-facing | Internal IT |
| --- | --- |
| Acknowledge the concern | State the situation clearly |
| Confirm the issue | Identify urgency/business impact |
| Show professionalism | Recommend next steps |
| Explain next steps | Concise technical language |
| Realistic expectations | No unnecessary emotion |
| Avoid blame | |

## Inform, report or escalate?
| Level | When | Example |
| --- | --- | --- |
| **Inform** | Low urgency, awareness | Printer low on toner |
| **Report** | Needs tracking/handling | Unauthorized software on a workstation |
| **Escalate** | Higher risk, urgency, authority or policy concern | Former employee still has VPN access |

* Practice: laptop won't connect before tomorrow's presentation → report (priority) · former employee account active → **escalate** · private files visible to the wrong department → **escalate** (privacy)

## S-I-R messages
**Situation** - what's happening? · **Impact** - why does it matter? · **Recommendation** - what should happen next?

| ❌ Weak | ✅ S-I-R |
| --- | --- |
| "Jordan's laptop is messed up and they're upset. Someone needs to fix it before tomorrow." | **S:** Jordan's newly provisioned laptop has projector connection issues, unreliable Windows Hello and pending updates. **I:** Jordan presents tomorrow morning; this affects classroom delivery and suggests a gap in the deployment process. **R:** Prioritize troubleshooting today, confirm projector connectivity, complete updates, and review whether the deployment checklist was completed. |

## A strong user-facing response
* ✅ Acknowledge frustration/urgency · confirm the main concern · explain what happens next · realistic timeline · calm, professional tone
* ❌ "That's not our fault." · "Submit separate tickets." · "We'll definitely fix everything today." · long robotic responses

## AI critique
* AI drafts can be **polished but vague**, professional but unrealistic, friendly but missing next steps, too long, **confident but inaccurate**
* The sample AI reply to Jordan: apologetic filler, generic "restart and check updates", pushes the user to submit a ticket, **ignores the presentation deadline**, no ownership
* > AI can draft, but **human judgment** decides what the message must accomplish

## Good communication is
**Clear · Concise · Audience-aware · Professional · Action-oriented · Based on careful listening**
> If the right person can't understand the situation, the impact and the next step, **the message isn't finished**.
