# Resume Workshop and Job Posting Analysis
Back to [[SYSA1011]] · Prev: [[Hiring Decisions and Candidate Evaluation]] · Next: [[Ethics in IT Decision Making]]

> [!quote] Not about making a resume look pretty - it's about how employers evaluate candidates and how to get selected for an interview.

## The hiring problem
* A help desk posting gets **300+ applications in 48 hours**
* Modern process: **Job posting → Applications → ATS screening → Recruiter review → Hiring manager review → Interviews → Selection**
* **The first "person" reviewing your resume may not be a person**

## Applicant Tracking Systems (ATS)
* Manage volume, **search for skills/keywords**, categorize candidates, build shortlists
* They **don't hire** anyone - but they filter people out before a human sees them

| Posting says | Resume says | ATS result |
| --- | --- | --- |
| "Active Directory experience required" | "Managed user accounts" | ❌ no match |
| "Active Directory experience required" | "Created and managed **Active Directory** user accounts using **Microsoft 365** admin tools" | ✅ match |

> [!tip] Speak the employer's language
> Use the posting's terminology where it's true. Not gaming the system - **communicating clearly**.

### Activity - find the keywords
* In a posting, list: **technical skills**, **certifications**, **soft skills**, **repeated terms**

## AI and hiring
| ✅ Appropriate | ❌ Risky |
| --- | --- |
| Brainstorming bullet points | Inventing experience |
| Improving wording | Claiming skills you lack |
| Resume critique | Generic AI language |

* Employers know resumes may be AI-written, so they add **skills assessments**, **practical demonstrations**, **portfolio reviews**, **behavioural interviews**
* > "Results-oriented professional with proven ability to leverage innovative solutions and synergize cross-functional initiatives." - tells a hiring manager **nothing**. Replace filler with evidence

## What employers look for
* Technical skills, professionalism, communication, reliability, problem solving, teamwork, willingness to learn
* > **Technical skills get you considered. The rest get you hired.**

## Beyond the resume
* **LinkedIn**, **GitHub**, **portfolio**, **online presence** (digital footprint), **professional communication** (emails, interview conduct, follow-ups) - see [[LinkedIn and Digital Professionalism]]

## Anatomy of a strong resume
1. Contact information
2. Professional summary
3. Skills
4. Experience
5. Education
6. Certifications
7. Projects

Every section answers: ***"Why should we interview this person?"***

## Experience vs responsibilities
| Weak | Stronger |
| --- | --- |
| "Responsible for supporting users." | "Provided technical support to **150+ users** and resolved common workstation issues." |
* Show **results, outcomes, scope, impact**

## Building experience as a student
* **Projects** show initiative, technical ability, problem solving, communication
* Home lab, website, Linux server, volunteer work, documentation (this vault counts!)

## Resume red flags
* Doesn't match the posting · poor spelling/grammar · generic AI language · missing contact info · no evidence of accomplishments · irrelevant info · no customization

### Critique activity
| Candidate | Profile |
| --- | --- |
| A | Excellent technical skills, terrible grammar |
| B | No work experience, strong projects |
| C | AI-generated content, no personal voice |
* Who gets an interview? **Justify with evidence**, not preference

## Tailoring
* **One person, three jobs, three resumes**

| Help Desk Technician | Junior Systems Administrator | Project Coordinator |
| --- | --- | --- |
| Customer service | Infrastructure | Organization |
| Communication | Servers | Documentation |
| Troubleshooting | Networking | Communication |
