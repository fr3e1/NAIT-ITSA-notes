# Project Planning Phase and RACI
Back to [[PMIT1027]] · Prev: [[Gantt Charts and Critical Path]] · Next: [[Change and Risk Management]]

## How we got here
| Document | Answers |
| --- | --- |
| Charter | **Why** the project exists |
| Scope | **What** is included/excluded |
| WBS | **What work** must be done |
| Schedule (MS Project) | **When** the work happens |

* Now: integrate everything into one **Project Plan** - the roadmap for execution, monitoring and closing

## Goals of the planning phase
* Validate earlier assumptions and estimates
* Assign roles and responsibilities
* Identify resources and procurement needs
* Develop supporting plans: **risk, communication, change, quality**
* Get **stakeholder approval**

## Key questions
| Question | Section |
| --- | --- |
| Why are we doing this? | Charter review / objectives |
| What will be delivered? | Scope + WBS |
| Who does the work? | Roles / **RACI** |
| When and how long? | Schedule |
| How will we manage risk, change, communication? | Risk, change, communication plans |
| How much will it cost? | Budget / procurement |

## Project Plan Report sections
* **Revise** (don't just copy): objectives (from the charter), scope (new in/out items + acceptance criteria per deliverable), WBS (dependency notes, table/diagram in appendix), schedule (milestones with dates, **critical path + float**, screenshot + link to the shared `.mpp`)
* **Add:** roles & responsibilities (RACI + role descriptions + authority), procurement plan, risk + change plans, communication plan, budget/cost summary (Excel table), **approval and sign-off** (*"This project plan was reviewed and approved by the sponsor and project team on [date]."*)

## RACI chart
* Many projects fail because nobody's sure **who does what** - RACI makes responsibilities visible
* Tasks down the side, people/roles across the top, a letter in each cell

| Letter | Role | Think |
| --- | --- | --- |
| **R** - Responsible | Does the work (can be several) | "Who's getting it done?" |
| **A** - Accountable | Owns the outcome, final decision - **exactly one** per task | "Who signs off / takes the blame?" |
| **C** - Consulted | Gives input/expertise - **two-way** | "Who do we talk to before acting?" |
| **I** - Informed | Kept updated - **one-way** | "Who needs to be kept in the loop?" |

> [!TIP]
> Rule: every task has **one A**, **at least one R**, and optional C's and I's

### Example - Gamescom watch party
| Task | Event Lead | Tech Setup | Communications | Snacks/Logistics | Attendees |
| --- | --- | --- | --- | --- | --- |
| Book viewing room | A/R | | | | I |
| Set up livestream + sound | | A/R | | | I |
| Promote event | C | | A/R | | I |
| Organize snacks | C | | | A/R | I |
| Host / welcome guests | A/R | C | C | C | I |
| Photos / highlights | C | C | A/R | | I |
| Feedback + wrap-up | A/R | | C | | I |

### Benefits
* Clear ownership · no duplicated or missed work · less confusion in busy phases · fast onboarding · evidence for the plan report

### Common mistakes
* Too many **A**s → no clear owner
* Missing **C**s → poor collaboration
* Forgetting **I**s → surprises
* Not updating when roles change
